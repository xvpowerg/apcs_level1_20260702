BST 刪除的核心規則

先找節點： val < self.data 往左；val > self.data 往右；相等才真正進入刪除。

情況 A：沒有左子樹

tmp = self.right，最後 return tmp。父節點拿到這個回傳值後，會把原本指向你的連線改成指向右子樹。

情況 B：沒有右子樹

完全相反，return self.left，讓左子樹接替目前節點。

情況 C：左右子樹都有

不能直接拔掉，否則左右兩棵樹不知道怎麼接。這份程式採「左子樹最大值」當前驅：先把前驅值複製到目前節點，再到左子樹把那個重複的前驅刪掉。

為什麼一定要 return，再由父節點接回？

因為刪除後，原本那個位置的「子樹根」可能換人。

self.left = self.left.delete_l(val)

右邊遞迴刪除後會回傳「刪完之後，這棵左子樹的新根」。父節點再用等號把左指標接回去。

葉節點：回傳 None → 父節點的 left/right 變 None。
只有一個子樹：回傳那個孩子 → 孩子直接升上來。
左右都有：節點本身通常仍是這棵子樹的根 → 最後 return self。

所以這裡的 return 不只是「函式結束」，而是在告訴父節點：「刪完後你現在應該指向誰」。

maxNode() 為什麼往右走？

BST 的規則是「左小右大」。因此在一棵子樹裡，最大值一定一路往右找。

ptr = self
while ptr.right:
    ptr = ptr.right
return ptr

刪除一個左右都有孩子的節點時，本程式用左子樹最大值當作替身，也叫「中序前驅 predecessor」。它一定比原節點小，但又是左子樹中最接近原節點的那個值，因此補上後仍能維持 BST 大小關係。

你的程式：兩個值得補充的邊界情況

1. 主程式最好接住根節點的回傳值
目前是 bst.delete_l(n)。若「根節點本身」剛好只有一個子樹或是葉節點，delete_l() 會回傳新的根，但主程式沒有接住。較通用寫法是：
bst = bst.delete_l(n)
2. self.left=None 是較特殊的簡化
當前驅剛好就是 self.left 時，你的程式直接把左子樹設為 None。若那個前驅本身還有左孩子，就會一起被丟掉。通用寫法通常會統一寫成：
self.left = self.left.delete_l(tmp.data)

這份動畫仍以你原本的程式為主；上面只是補充「一般 BST 寫法」需要注意的地方。你目前給的原始資料在示範刪除 20、15、4 等案例時，可以正常觀察核心刪除流程。
